Everything a library needs

Built around the way people actually look for a picture: roughly when it happened, who was there, or what was in the frame.

A timeline that scrolls decades

Photos group by the day they were taken, with a year rail down the side so a jump to 2013 is one click, not a minute of scrolling.

People, found automatically

Faces are detected and clustered as photos arrive. Name someone once and every picture of them is grouped — merge, split, or correct a wrong match at any time.

Search by what's in the picture

Describe the shot — "a dog on a beach" — and get results without a single tag or filename. Filenames, dates, albums and folders are searchable too.

Duplicates worth reviewing

Perceptual hashing finds re-saved, resized and re-sent copies of the same shot — not just identical files — and groups them so you choose what to keep.

Albums and real folders

Upload a folder and its structure comes across intact. Albums sit alongside, so curated sets and the original tree can both exist.

Accounts you control

Invite family by email, or create local accounts directly. A locked area keeps private photos out of the main timeline.

No one else is in the loop

Every part of Imadeo runs on your machine — including the parts that recognise faces and understand what a photo shows.

Run it yourself

Imadeo needs Postgres, Redis and a machine-learning worker. Clone the repository and start the stack: 

# grab the source
git clone https://github.com/eranabir/imadeo.git
cd imadeo

# start Postgres, Redis and the ML worker
docker compose up -d postgres redis machine-learning

# install dependencies and run the app
yarn install
yarn dev

Imadeo is under active development and does not yet ship packaged Docker images or desktop installers — for now it runs from source. Check the repository for the current state before pointing it at a library you care about, and keep your own backups.
